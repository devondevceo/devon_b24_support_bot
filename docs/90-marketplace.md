### ПОЛЕ 3. ОПИСАНИЕ РЕШЕНИЯ

```
Клиенты пишут в Telegram, а задачи живут в Битрикс24. Между ними — ручной
перенос: скопировать сообщение, открыть портал, создать задачу, вернуться в
чат, отписаться. Половина обращений теряется по дороге, а «поставил ли кто-то
задачу по этому сообщению» превращается в ежедневный вопрос.

Приложение подключает к порталу вашего Telegram-бота и превращает общие чаты
с клиентами в рабочий контур поддержки: обращение из чата становится задачей
Битрикс24 в два касания, а всё, что происходит с задачей на портале, само
возвращается в чат.

ЧТО УМЕЕТ БОТ В ЧАТЕ

• Создание задачи ответом на сообщение клиента, командой /task или кнопкой.
  Вложения переносятся в задачу (до 20 МБ), дубликаты не создаются даже при
  повторной отправке.
• Настраиваемый опросник: категории обращений и вопросы задаёте сами, ответы
  попадают в нужные поля задачи (приоритет, срок и любые пользовательские).
• Уведомления о событиях задач: создание, статус, стадия канбана, срок,
  ответственный, комментарии. Какие события и в какой чат — настраивается;
  поток можно сгруппировать в сводку раз в N минут, чтобы не заваливать чат.
• Комментарии в обе стороны: реплика из чата уходит в задачу, комментарий из
  задачи — в чат.
• Карточка задачи с действиями: завершить, взять в работу, пауза, перенос по
  стадиям канбана, смена срока, ответственного, приоритета.
• Сводка по стадиям канбана, списки задач с фильтрами, утренняя сводка по
  расписанию и напоминания о сроках.
• Учёт времени: списание из чата командой /time, кнопкой карточки или из
  мини-приложения; отчёт по месяцам в разрезе статусов и стадий, отдельной
  строкой — трудозатраты на поддержку.
• Подтверждение новых задач ответственным (опционально): задача не начинает
  жить, пока назначенный человек не решит, и решение двигает её по канбану.

МИНИ-ПРИЛОЖЕНИЕ TELEGRAM

Полноценный интерфейс задач, открывается прямо из чата или из меню бота:
списки с фильтрами, карточка, создание полной формой, правка полей,
комментарии, вложения, сводка и учёт времени. Ничего не нужно устанавливать —
это встроенные мини-приложения Telegram.

ВНУТРИ БИТРИКС24

Экран настройки для администратора: подключение бота, привязка чатов к
проектам, конструктор опросника, настройка уведомлений, назначение
администраторов, тег поддержки для отчёта по трудозатратам.

КАК ЭТО УСТРОЕНО

• Бот — ваш собственный, созданный в Telegram за минуту. Название и аватар —
  вашей компании, переписка клиентов не проходит через чужих ботов.
• Задачи создаются и меняются от имени конкретного сотрудника: каждый
  привязывает свой аккаунт Telegram к своему пользователю Битрикс24 (команда
  /link или кнопка в приложении). Права проверяет сам Битрикс24 — приложение
  их не расширяет и не сужает.
• Один чат — один клиент: задачи из чата попадают только в привязанные к нему
  проекты, чужие задачи из чата не видны и не открываются.

КАКИЕ ДАННЫЕ ИСПОЛЬЗУЕТ ПРИЛОЖЕНИЕ

• Переписка чатов НЕ сохраняется: сообщения обрабатываются на лету, а в
  Битрикс24 попадает только то, из чего сотрудник явно создал задачу или
  комментарий.
• Ключи доступа хранятся в зашифрованном виде, данные — на серверах в России.
• При удалении приложения с портала данные хранятся 30 дней (на случай
  переустановки), затем удаляются безвозвратно. Подробности — в политике
  конфиденциальности, ссылка в карточке.

ТРЕБОВАНИЯ И ОГРАНИЧЕНИЯ

• Нужен собственный бот Telegram: он создаётся бесплатно в официальном
  @BotFather за одну минуту, инструкция — в разделе «Установка».
• Для установки и настройки нужны права администратора Битрикс24.
• Работает с облачным Битрикс24 на тарифах с поддержкой REST API
  (Битрикс24.Маркет). Коробочная версия не поддерживается.
• Бот видит сообщения только тех групповых чатов, куда вы сами его добавили.
• Создавать и менять задачи могут сотрудники, привязавшие свой Telegram к
  учётной записи Битрикс24; права на задачи определяет портал.
• Telegram должен быть доступен вашим сотрудникам и клиентам.
```

### ПОЛЕ 4. УСТАНОВКА РЕШЕНИЯ

```
Настройка занимает 10–15 минут и выполняется администратором Битрикс24.

ШАГ 1. УСТАНОВИТЕ ПРИЛОЖЕНИЕ

Нажмите «Установить» и подтвердите права доступа. После установки откройте
«Поддержка в Telegram» в левом меню портала — мастер настройки проведёт по
трём шагам: бот, чат, проект.

ШАГ 2. СОЗДАЙТЕ TELEGRAM-БОТА

Бот создаётся в официальном сервисе Telegram и принадлежит вам.
1. Откройте в Telegram диалог с @BotFather.
2. Отправьте команду /newbot, задайте имя (например, «Поддержка ВашаКомпания»)
   и техническое имя, заканчивающееся на bot.
3. Скопируйте выданный токен вида 1234567890:AA... — целиком.
Токен даёт полный доступ к боту: не отправляйте его в чаты и никому не
пересылайте — вводите только в поле на следующем шаге.

ШАГ 3. ПОДКЛЮЧИТЕ БОТА К ПРИЛОЖЕНИЮ

В приложении, на вкладке «Бот», вставьте токен в поле и сохраните. Приложение
проверит токен, настройки и покажет состояние подключения. Токен нигде не
отображается обратно и хранится в зашифрованном виде.

ШАГ 4. ДОБАВЬТЕ БОТА В РАБОЧИЙ ЧАТ

Добавьте бота участником в групповой чат Telegram, где идёт переписка с
клиентом. Чат появится в приложении на вкладке «Чаты» сам, через несколько
секунд.

ШАГ 5. ПРИВЯЖИТЕ ЧАТ К ПРОЕКТУ

На вкладке «Чаты» нажмите «Привязать проект» у нового чата и выберите проект
(рабочую группу) Битрикс24, куда должны попадать задачи из этого чата. Один
чат обслуживает одного клиента; проектов может быть несколько.

ШАГ 6. ПРИВЯЖИТЕ СВОЙ TELEGRAM

Отправьте боту в личные сообщения команду /link и войдите в портал по
ссылке — аккаунты свяжутся. То же самое делает кнопка «Привязать Telegram» на
главном экране приложения. Каждый сотрудник делает это один раз; задачи
создаются от его имени.

ШАГ 7. ПРОВЕРЬТЕ РЕЗУЛЬТАТ

В рабочем чате ответьте на любое сообщение командой /task — бот покажет
превью задачи и кнопку «Создать». Созданная задача откроется в Битрикс24, а
изменения по ней начнут приходить в чат.

ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ

• «Бот не подключён» на вкладке «Бот» — токен не введён или не прошёл
  проверку; повторите шаг 3.
• Чат не появился на вкладке «Чаты» — убедитесь, что бот добавлен именно в
  групповой чат (не в личку) и напишите в чате любое сообщение.
• «Задача не найдена в проектах этого чата» — задача принадлежит проекту,
  который не привязан к этому чату; проверьте шаг 5.
• Бот просит привязать аккаунт — выполните шаг 6: без привязки задачи
  создавать нельзя, права проверяет Битрикс24.
```

## 3. Scope: минимальный набор и обоснование для модератора

Инвентаризация всех вызовов REST в коде (30.08.2026, `grep` по `src/b24bot`):

| Scope | Зачем (методы) |
|---|---|
| `task` | всё про задачи: `tasks.task.*`, `task.stages.get` (канбан), `task.commentitem.add`, `task.elapseditem.*` (учёт времени), `task.item.userfield.*` (поля опросника) |
| `sonet_group` | список проектов и участников: `sonet_group.get`, `sonet_group.user.get`, `sonet_group.user.groups` |
| `im` | чтение комментариев задач — они живут в чате задачи: `im.dialog.messages.get` (docs/00-portal-facts.md §5.1) |
| `disk` | вложения из Telegram в задачу: `disk.storage.getlist`, `disk.storage.getchildren`, `disk.folder.uploadfile` |
| `user_basic` | опознание и имена сотрудников: `user.current`, `user.get`, `user.admin` |

Пилотный «максимально широкий scope» (70 прав) был решением для локального
приложения — смена scope у него роняла все привязки разом. Тиражному приложению
права выдаёт карточка, и лишние — типовая причина отказа модерации. `event` и
`placement` отдельными scope не запрашиваются — их в кабинете нет (проверено
на mclick).

⚠️ Проверить на первом smoke-прогоне тиражного приложения: достаточно ли
`user_basic` для `user.admin` и полей `user.current`. Если нет — поднять до
`user` с готовым обоснованием: «сопоставление сотрудников — основной
функционал» (требование раздела «Пользователи» в правилах Маркета).

## 9. Миграция пилота с локального приложения

Опыт mclick (`bitrix_app.go`, ветка migrate) — главная ловушка «гибридного
состояния»: локальный `client_id` + тиражный `refresh_token` даёт вечный
`invalid_grant`, а старое локальное приложение продолжает слать события со
СВОИМ `APPLICATION_TOKEN` и может перехватывать их у нового.

Порядок для `devondev.bitrix24.ru` (единственный портал на локальном приложении):

1. Дождаться публикации тиражного приложения в Маркете.
2. Поставить его на портал ИЗ каталога — рядом с локальным. Установка создаст
   того же теннанта по `member_id` (upsert) и перепишет `APPLICATION_TOKEN` и
   scope на тиражные; личные привязки (`/link`) сотрудники пройдут заново —
   OAuth-грант локального приложения на тиражное не переносится.
3. Удалить локальное приложение на портале (Разработчикам → интеграции).
   Наш `ONAPPUNINSTALL`-обработчик при этом НЕ тронет теннанта: подтверждение
   И-8 увидит, что `app.info` тиражными кредами живо. Событие удаления
   локального придёт со старым токеном и не пройдёт сверку — это штатно.
4. Проверить: `event.get` содержит 8 подписок, уведомления ходят, `/link`
   работает, `app.info` показывает статус `S`/`P`.

Один `.env` несёт одну пару кредов — сервер переводится на тиражные в момент
шага 2 (не раньше: до установки из Маркета refresh пилотных токенов тиражными
кредами невозможен, окно простоя привязок — между шагом «креды в .env» и
повторными /link сотрудников; спланировать на вечер).
